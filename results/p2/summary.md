# P2 predictor development (n <= 330) — summary

Dev splits 1-3 (R = 10 shared R0 random trajectories each, P1 permutations and model seeds) + re-split check (R = 10, n <= 330). Parent P* = stack_lr_wr2 (upstream params). Paired contrasts on E_fixed_dev: Var(d_r)/R + V_Q(d-bar), stratified query bootstrap B = 2000 shared by parent and candidate (weights 'p2_gate'). Gate (DESIGN §8): mean relative gain over n in {30,160,330} x 3 splits >= 2%; 95% CI at n = 160 excludes 0 on >= 2/3 splits; same sign on the re-split. P2 additions, stricter than DESIGN: <= 1% relative loss at n = 660 and a cap of 10 configurations (protocol.yaml gate); the frozen P* is the passing configuration with the largest mean gain (a P2 choice, not a DESIGN rule). Generated by `scripts/30_p2_predictor.py summary`.

**Interpretation (independent review, docs/reviews/p2_predictor_review.md).** The gain is best read as +4.0-4.5%, the best of 10 adaptively designed dev configurations without independent confirmation. Configurations 7-10 were designed after interim looks that included the re-split and n = 660, so the re-split is not a blind check. The gi300 component alone fails the gate; dense_arr_aprior alone gives +4.00%. The gain is certainly positive (about 8 SE at n = 160), but its size is optimistic by perhaps 0.3-0.5 points. It is about +0.001-0.003 AUPRC in absolute terms and has been validated on random trajectories only. The final evaluation on T is unaffected by this selection.
